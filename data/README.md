# Data Documentation: EmoReact Dataset & Preprocessing

This directory documents the data management, structure, and preprocessing pipeline for the **Multimodal Emotion-to-Sentiment Derivation and Mapping** project (Phase 1).

---

## 1. Dataset Overview

The project uses **EmoReact (Version 1.0)** as its primary empirical foundation:
- **Research Topic**: Understanding multimodal affective and emotional expressions of children reacting to diverse stimuli.
- **Total Samples**: 1,102 audio-visual video clips.
- **Data Partitions**: Split in a person-independent manner (subjects in training do not appear in validation or test sets):
  - **Train**: 432 clips (39.2%)
  - **Validation**: 303 clips (27.5%)
  - **Test**: 367 clips (33.3%)
- **Raw Dataset Location**: `datasets/EmoReact_V_1.0/`

## 3. Modality Specifications

| Modality | Status in Raw Dataset | Format / Encoding | Characteristics |
| :--- | :--- | :--- | :--- |
| **Video** | Present | H.264 / MP4 | 1,034 clips at 1280x720, 68 at 640x360; 947 at 23.976 FPS, 155 at 29.97 FPS; durations 2.8s - 14.3s. Resized to $224 \times 224$ for ResNet-18. |
| **Audio** | Present (in MP4) | AAC Stereo | 44.1 kHz, 2 channels; standardized to 16 kHz mono 16-bit PCM WAV; 64-band Log-Mel Spectrogram input contract. |
| **Visual Features** | Present | Plain text / CSV | OpenFace 1.0 (`.params.txt`, `_au.txt`, `_gaze.txt`) per clip. |
| **Text** | Not Present | None | EmoReact V1.0 does not include speech transcripts; handled as optional/None with attention masking. |

> [!NOTE]
> Following `AGENTS.md` Stage 1 specifications, textual inputs are optional. The standardized manifest records `text: null` and `modality_availability.text: false` without failing or discarding samples. If textual features are enabled in later stages, automatic speech recognition (ASR via Whisper) can be applied.

## 4. Annotation Schema & Labels

Each row in `Labels/*_labels.text` consists of **9 comma-separated numerical values**:

1. **Columns 0 to 7 (Discrete Multi-label Emotions)**:
   - Values are binary: `0` (absent) or `1` (present).
   - Column index mapping:
     - `0`: **Curiosity** (34.9% positive across dataset)
     - `1`: **Uncertainty** (31.2% positive)
     - `2`: **Excitement** (32.2% positive)
     - `3`: **Happiness** (54.8% positive - dominant class)
     - `4`: **Surprise** (27.0% positive)
     - `5`: **Disgust** (12.4% positive)
     - `6`: **Fear** (4.5% positive - severe minority class)
     - `7`: **Frustration** (11.9% positive)
2. **Column 8 (Continuous Affective State)**:
   - **Valence**: Real value on a continuous 1.0 to 7.0 Likert scale (mean: 4.27, std: 1.34).
   - Represents the affective pleasantness rated by human annotators.

> [!IMPORTANT]
> **No Fabricated Sentiment**: Emotion labels (e.g. *Happiness*, *Fear*) and affective state (*Valence*) are preserved in their exact original form. No artificial binary/ternary "sentiment" labels (positive/negative/neutral) are fabricated during preprocessing. Sentiment derivation is exclusively learned in downstream architecture stages.

### Multi-Label Imbalance & Training Loss Weights

To address severe class imbalance during multi-label classification, positive weights ($\text{Pos\_Weight}_e = \frac{N_{\text{neg}}}{N_{\text{pos}}}$) are computed for `torch.nn.BCEWithLogitsLoss`:

| Emotion Category | Train Positives ($N=432$) | Train Prevalence (%) | BCE `Pos_Weight` Ratio |
| :--- | :--- | :--- | :--- |
| **Happiness** | 224 | 51.85% | 0.9286 |
| **Curiosity** | 148 | 34.26% | 1.9189 |
| **Excitement** | 144 | 33.33% | 2.0000 |
| **Uncertainty** | 132 | 30.56% | 2.2727 |
| **Surprise** | 114 | 26.39% | 2.7895 |
| **Disgust** | 60 | 13.89% | 6.2000 |
| **Frustration** | 53 | 12.27% | 7.1509 |
| **Fear** | 17 | 3.94% | 24.4118 |

- **64.8%** of samples contain 2 or more co-occurring active emotions.
- **12.5%** of samples have 0 active emotion labels (pure affective valence rating).

## 5. Preprocessing Pipeline

The preprocessing workflow is implemented in `src/sentiment_derivation/data/preprocessing.py` and executed via `scripts/prepare_data.py`.

### Responsibilities
1. **Annotation Validation**: Checks column counts, parses binary flags, and validates continuous valence bounds ($[1.0, 7.0]$).
2. **Media Matching**: Discovers video stems sorted alphabetically in ASCII order, matching them 1:1 with corresponding label rows.
3. **Integrity Verification**: Verifies video headers and decodability using OpenCV; detects corrupted or missing files.
4. **Visual Feature Verification**: Confirms presence of OpenFace triplets (`.params.txt`, `_au.txt`, `_gaze.txt`).
5. **Optional Audio Standardization**: Extracts standardized 16 kHz mono 16-bit PCM WAV files from MP4 clips via FFmpeg.
6. **Canonical Manifest Generation**: Serializes full sample records and dataset statistics into `data/processed/processed_manifest.json`.

## 7. How to Run

### Step 1: Activate Virtual Environment
```powershell
.\venv\Scripts\Activate.ps1
```

### Step 2: Run Dataset Exploration Notebook
Open and execute `notebooks/01_dataset_exploration.ipynb` in VS Code or Jupyter:
```powershell
jupyter notebook notebooks/01_dataset_exploration.ipynb
```

### Step 3: Run Preprocessing Pipeline
Generate the standardized processed manifest and summary report:
```powershell
python scripts/prepare_data.py
```

To additionally extract standardized 16 kHz mono WAV audio tracks for all clips:
```powershell
python scripts/prepare_data.py --extract-audio
```

### Step 4: Run Automated Tests
```powershell
python -m pytest tests/test_data.py -v
```
